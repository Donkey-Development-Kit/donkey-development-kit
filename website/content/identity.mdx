# Identity

<Callout type="info">
  **Phase 2 — designed, not yet shipped.** The API shape below is a proposal.
  The exact token-exchange endpoint and header the gateway expects are
  **unverified**, and will not be guessed. See [Roadmap](/roadmap) and
  [Verification policy](/concepts/verification).
</Callout>

By default the gateway sees your **service**, not the person the agent is
acting for. That is fine until policy depends on who is asking.

```python
async with donkey.as_user(id_token=slack_user_oidc_token):
    await hr_bot.answer(question)      # the gateway sees the user, not just the service
```

Inside that block, a user-scoped token is acquired via RFC 8693 token exchange
and attached to every governed call, so the gateway's Trusted Agent Identity
layer can apply per-user policy.

## The problem this actually solves

An HR bot must not answer a manager's salary question about a *different*
manager's report.

That decision belongs to the gateway — it is the component that holds the
identity policy, the org chart relationships, and the audit obligation. The
SDK's entire job is to get the user's token onto the request correctly so the
gateway can make the call it is already able to make.

## The boundary, stated plainly

<Callout type="warning">
  **This does not implement authorisation logic.** Trusted Agent Identity is a
  shipped MuleSoft feature. The SDK does the token-exchange plumbing and header
  placement — nothing more. "Check the user's role in the SDK" is client-side
  enforcement, and it is on the [will-not-build list](/roadmap): code in your
  process can be bypassed by code in your process.
</Callout>

## No silent fallback

The failure mode worth designing against is a token exchange that quietly
fails and lets the call proceed under the **service** identity. That would
mean per-user policy silently stops applying while everything still appears to
work — the worst possible outcome, because nothing looks broken.

So entering `as_user()` either attaches a user-scoped token or raises. It never
degrades to the service identity without telling you.
