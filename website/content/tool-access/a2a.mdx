# A2A agent tools

Agent Broker is an A2A server, and A2A-compliant agents in the registry can be
consumed directly from Python. `AgentHandle.as_tool()` wraps a remote A2A
agent as a callable tool in each framework — the same "resolve, then bind"
shape as MCP tools, just for a remote agent instead of a remote tool server.

```python
handle = await donkey.registry.resolve_agent("com.acme/claims-triage-agent/1.0.0")
tool = handle.as_tool()          # callable in your framework's native tool shape

agent = create_react_agent(donkey.langgraph.chat_model("gpt-4o"), [tool])
```

This is what lets a Python agent **delegate** to an Agent Broker agent without
the developer learning the A2A protocol. Under the hood, `as_tool()` uses the
community `a2a-sdk` for the protocol handling — the SDK does not implement
JSON-RPC itself.

## Install

A2A support is secondary but cheap, and ships behind its own extra so it
doesn't add a dependency to installs that only need MCP tools:

```bash
pip install "donkey-kit[a2a]"
```

## Where this fits

- `AgentHandle` comes from `ExchangeRegistry.resolve_agent()` — the same
  registry surface that resolves MCP servers into `McpServerHandle`s. See
  [Discovery, search & filter](/tool-access/discovery).
- `as_tool()` returns a framework-native callable, following the same
  per-framework binding conventions as [Framework binding](/tool-access/binding).
