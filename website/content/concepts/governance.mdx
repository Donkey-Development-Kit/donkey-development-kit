# Governance

"Governance" is what the Omni Gateway proxy adds on top of a plain model call:
authentication, attribution, routing, and policy enforcement — applied at the
gateway, not in your code.

## What the gateway enforces

The live-verified `openai-sdk` proxy carried this policy stack, all enabled:

- **client-id-enforcement** — the `client_id` + `client_secret` header pair is
  required; this is also the per-agent identity (see [Attribution](/concepts/attribution)).
- **model-based-routing** — routes on the `model` field in the request body to a
  provider; response carries `x-llm-proxy-*` routing headers.
- **llm-proxy-core**, **cors**, **dataweave-headers-transformation**,
  **openai-transcoding-policy**.
- Optionally applied for capture: **llm-token-rate-limit** and
  **llm-pii-detection** — these produce the `429` and `403` rejection shapes in
  the [Error taxonomy](/errors).

## What the SDK does with it

The SDK's job is to make governance **invisible when it passes and typed when it
blocks**:

- Injects the verified consumer-auth headers and attribution on every call.
- Retries transient failures in its own transport (frameworks are told
  `max_retries=0` so retries happen in one place).
- Maps policy rejections to typed exceptions via `classify()`.

## The `Governance` object (roadmap)

The plan defines a `Governance` object with three verbs — inspect a governed API
instance, `resolve()` its policy state with drift detection, and `simulate()`
locally — plus a policy-portability table (which policies are Connected-Mode-only
vs. Local-Mode-capable).

<Callout type="warning">
  These are **structural today, not wired**. Reading applied policies per API
  instance is confirmed via the Anypoint CLI, but the governed-state join and
  local-mode viability are still unverified. The object raises
  `blocked on verification` rather than report a state it can't confirm. See
  [Verification policy](/concepts/verification).
</Callout>
